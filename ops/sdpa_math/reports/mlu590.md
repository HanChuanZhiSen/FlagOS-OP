# mlu590 移植报告: sdpa_math（`aten::_scaled_dot_product_attention_math`）

> 日期: 2026-11-25 · 提交: 87bad0986134bc33defd3567f9a117f43dade5f2
> 环境: torch_mlu 1.33.1+torch2.11.0 / CNRT 7.7.2 / CNNL 2.2.14 /
> Driver 6.5.52 · 无 vLLM runtime
> 用卡: mlu:0（`MLU_VISIBLE_DEVICES=7 → mlu:0`）
> 环境锁: `configs/env/mlu590.lock.yaml`（2026-09-23 采集，Driver

## 1. 分叉判定（§2a）

| 算子 | 结论 | 理由 |
|---|---|---|
| T3 `ops/sdpa_math` | **结构级** | 同 p800；须物化第二输出 P（不整体换 flash）；同构 vendor O/LSE + exact-P，差异在 LSE 布局和 vendor 约束，见 PLATFORM.md §3b |

## 2. 环境与首测（§2b）

- 设备: MLU590-M9 × 8，用卡 mlu:0
- 栈: torch 2.11.0+cpu + torch_mlu 1.33.1 / triton 3.4.0+mlu2.1.1 /
  flag_gems 5.3.5 · 无 vLLM
- `PYTHONPATH=/workspace/FlagOS-OP`；测试设备 `SDPA_MATH_TEST_DEVICE=mlu:0`

首测结论：

| 项 | 结果 |
|---|---|
| exact-P | fp16/bf16 maskless、masked、GQA、bool/float mask 全达标 |
| LSE shape | `(B,Hq,Sq)` 精确，无 pad（Sq=100 → 100） |
| 注册 key | `AutogradPrivateUse1`（同 torch_npu） |
| qk_scale 约束 | 必须 ∈ (0, 1]；scale=8 时 vendor 报 `qk_scale value 8 is not in valid range (0, 1]` |

## 3. 实现决策（§2c）

| 决策 | 结论 |
|---|---|
| P 物化 | `exp(scale·QKᵀ + bias − LSE)`，Q/K 先升 FP32 再 matmul，分子加回与 vendor 一致的 bias（评审 P1-1） |
| 精确 mask 清零 | 全遮蔽行 NaN→0，残留 inf 报错（不静默掩盖，评审 P1-2） |
| scale 范围 | `_fast_eligible` 拒绝 scale > 1，fallback 到 torch_level |
| GQA | `repeat_interleave` 扩 KV（fused overrideable 无 `enable_gqa`） |
| 全遮蔽行 | vendor 可能返回有限值 → 显式 `masked_fill(0)` |
| fp32 / dropout | 回退 torch_level（fast path 只承接半精度、dropout=0） |
| direct requires_grad | 按设计 fallback torch_level（A1 forward 在 no_grad 下才走 fast path） |

## 5. 端到端

- **mini consumer**：framework_level 的 mini-decoder 双跑通过
  （logit_linf=0.0, top1=1.0, greedy=1.0, 打印行 ∇L∞=1.46e-11）
- **vLLM/目标引擎**：**未完成**。容器无 vLLM runtime（锁文件
  `quirks.no_vllm_runtime=true`），不能以 mini consumer 宣称完整交付。
  待有 runtime 后补 baseline/injected 两模式、目标阶段命中、输出对比
  和性能证据。

## 6. 性能启用边界与优化方向

**启用边界**：fast path 只在 fp16/bf16、dropout=0、scale ∈ (0,1]、
causal 方阵、无 fp32 mask 时启用；其余回退 torch_level。

**当前 speedup 0.577–0.718× 的原因**：`_materialize_p` 的 FP32 matmul
和逐元素 exp 没有融合进 vendor kernel，P 物化是独立的一段 ATen 组合。

**优化方向**：把 P 物化并入 vendor kernel 的后处理，或用 Triton 写
fused PV（参考 p800_custom_triton 的实验结论，MLU 上待验证）。
数值慢本身不等于结果无效——fast path 的价值是保留了 `(O, P)` 双输出
契约，性能优化是下一阶段的事。

## 7. 已知缺证

- 框架层入口（真实 vLLM）缺证，原因同上（无 runtime）。
- 跨层一致性 `run.py --consistency` 锚定 gelu_and_mul（A2）硬依赖
  flag_gems——MLU 容器有 flag_gems 5.3.5，但该锚定算子的 MLU 行为
  未验证，结构性缺证如实标注。
- 锁记录的 Driver 6.2.29 与本次实测 6.5.52 不一致，其余版本一致；
  原 kernel 顶注的 torch_mlu 1.34.1 未复测。
